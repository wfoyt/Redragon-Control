# 0.2.7 — Foreground lighting only

Remove live key/wheel remapping, input observation, tray, login startup and
background retry. These features required continuous input interception and
could cause missed or repeated key presses. Closing the window exits the app.
Lighting still saves onboard through an explicit transaction that closes afterward.

Normal launches disable legacy startup and stop old workers. Cleanup attempts
both workers even if one fails; a stuck tray cannot skip worker cleanup.
Reset also repairs corrupt legacy background preferences. Older profile bindings
remain readable but inert. No evdev/AppIndicator or virtual-input setup is needed.

## Install or update

Download `Redragon-Control-0.2.7-x86_64.AppImage` from this release and add it to
Gear Lever, or make it executable and launch it manually. Quit the older tray
using **Quit and stop keyboard services** before replacing your own copy.
The release also includes matching `.AppImage.zsync` and `.AppImage.sha256`
assets. Gear Lever discovers the embedded GitHub update source and offers
updates; users control update checking and installation. Older images without
metadata need one manual update or one-time update-source configuration.

Publishing this release does not replace an installed/system copy.

## Validation

All 134 tests passed with GTK enabled against source and against the new
AppImage’s bundled Python/GTK runtime, including last-window process exit,
legacy-worker cleanup and lighting descriptor cleanup. Subprocess tests use
the bundled loader when run inside an AppImage.

The embedded update string matches the required GitHub/zsync source exactly.
The zsync SHA-1 and Length match the 357,288,440-byte image, and its generated
SHA-256 sidecar verifies. Shell syntax and git whitespace checks pass.
The Flatpak wrapper could not allocate its document-portal path; the build used
a fresh dependency directory matching the lighting-only recipe and the installed
GNOME 50 runtime via `scripts/build-appimage.sh`.

No physical lighting writes or typing tests were performed. Automated tests do
not prove that unrelated hardware/firmware typing issues are resolved. The
user’s installed AppImage and normal app configuration were not modified.
